# UR7e + D435i 真实场景彩色重建测试报告

**测试日期：2026 年 9 月 28 日**  
**功能包：`ur7e_real_reconstruction`**  
**任务范围：真实设备接入 → 操作员手动多视角扫描 → 彩色 TSDF 表面重建 → 冻结保存与 RViz 预览**

## 1. 测试结论

本轮已完成真实 UR7e 与眼在手上的 D435i 多视角彩色重建。操作员确认“扫描完成”后，应用成功冻结为 `FROZEN`，最终融合 **859 帧**，记录 **35 个观察姿态**，生成 **17167 个顶点、24731 个三角形**。网格、原始 RGB/深度、双相机位姿和关节数据均已归档。

本功能包用于直观看到场景的物体位置、轮廓与颜色，辅助检查此前 ESDF 是否存在明显的几何偏差。它**不计算 ESDF，不向规划器提供输入，也没有机械臂运动指令接口**。

|---|---|---|

| RGB-D 输入与图像时间 TF | 通过 | 分别使用深度和彩色光学坐标系的标定与时间戳 |

“成功重建”表示数据融合和显示链路完成，不等于场景已无遗漏或精度已达标。

## 2. 测试目的及与此前 ESDF 的关系

此前 `ur7e_real_static` 的近表面预览按 **ESDF 距离**着色；本轮预览是由 **TSDF 提取的表面三角网格**，颜色来自 D435i 的真实彩色图像。

| 项目 | 此前 ESDF 扫描 | 本轮彩色重建 |
|---|---|---|
| 主要输出 | 静态规划距离场、近表面距离带点云 | 彩色表面网格、网格顶点点云 |
| 显示颜色 | 距离伪彩色 | 真实 RGB 融合颜色 |
| 地图坐标系 | `base_link` | `base_link` |
| 本次参数分辨率 | 2.5 cm | TSDF 体素 1.5 cm |
| 用途 | 后续静态避障规划的感知输入 | 人工观察场景，辅助几何对照 |
| 保存的逐视角原图 | 前次未归档 | 本轮 35 组已归档 |

两次测试并非同一轮同步采集，体素分辨率和显示对象也不同。前次 ESDF 显示包含约 ±5 cm 的近表面距离带，本轮显示 TSDF 表面；不能直接把两者外观厚度的差别判断为建图错误。

**本轮与此前 ESDF 共享相机及 TF/标定链。即使两种显示一致，也可能存在共同的标定误差。** 后续需要在场景未变化的前提下比较物体位置和尺度，再用独立尺寸/位置测量检验几何；ESDF 距离值还需单独检查。

### 3.2 标定链与图像处理

用户手眼外参定义为 `tool0 → camera_color_optical_frame`（子坐标系在父坐标系下的位姿，单位米）：

```text
T_tool0_color =
[[-0.706400704,  0.002414966, -0.707808034, -0.029901376],
 [ 0.707783955, -0.006516156, -0.706398905, -0.069185919],
 [-0.006318117, -0.999975854,  0.002893743, -0.012263443],
 [ 0.0,          0.0,          0.0,          1.0        ]]

T_base_color(t_color) = T_base_tool0(t_color) × T_tool0_color
T_base_depth(t_depth) = T_base_tool0(t_depth) × T_tool0_color × T_color_depth
```

`T_color_depth` 使用实际相机内部外参。运行时按两幅图像各自的时间查询 TF，并与同一校准模型的正运动学核对；不使用 SLAM，也不把彩色外参直接作为深度外参。

彩色图像按 CameraInfo 进行畸变处理后融入颜色层；本轮记录的彩色畸变系数均为 0，因此该配置下无需非零畸变校正。保存的 `rgb.png` 为原始彩色画面，未裁切、未美化。深度和彩色各自使用内参，不要求输入深度已对齐到彩色相机。

### 3.3 操作流程

1. 启动 UR 驱动，校验工厂标定；等待操作员在示教器启动 External Control。
2. 启动相机、安装 TF、重建节点及 RViz，运动控制器保持 inactive。
3. 先进行单视角真实数据验证，冻结保存 59 帧；这段数据与最终 859 帧会话分开存储。
4. 准备正式扫描时发现关节反馈链路异常；重启驱动，等待操作员再次启动 External Control，确认反馈恢复。
5. 开启新的正式扫描会话，由操作员通过示教器改变观察姿态；移动时跳过融合，停稳后采集。
6. 每个新观察姿态保存 RGB、深度、CameraInfo、TF、时间戳和关节角。
7. 操作员确认完成后，冻结融合、提取最后的完整网格、保存 PLY/NPZ，并核查全部文件。

### 5.4 视觉结果与限制

原始 RGB 中可见彩色积木、橙色瓶盖、试管架、容器及金属台面；最终彩色网格显示了部分对应的颜色区域和物体轮廓。多视角数据较初始单视角扩大了可见区域，但目前仍有明显孔洞、粗糙轮廓和未着色区域。

透明容器、金属反光、遮挡、彩色与深度视场差异，以及未完整建模的自身物体，都是需要对照排查的因素；本轮没有逐项隔离实验确认各误差的具体来源。**尚不能据本报告认定场景细节、物体尺寸或多视角重影已经通过验收。**

## 6. 软件测试和运行性能

### 6.1 软件测试

- 功能包编译通过；3 项输入单元测试通过，检查静止历史、反馈中断、无速度字段时的差分处理、RGB 图像格式与畸变处理。
- 独立 `ROS_DOMAIN_ID=83` 中使用合成 RGB-D/TF/关节输入，并实际调用 nvBlox/CUDA 进行融合。
- 检查空闲不融合、移动/错误 TF/空深度拒绝、关节反馈丢失后的停止与恢复、两个观察姿态保存、冻结、新扫描保留旧文件、延迟订阅与离线重载。
- 将后端 `update_esdf` 替换为“调用即失败”，完整重建流程仍通过。
- 合成 z=0.15 m 平面的顶点高度绝对误差 P95 约 **0.365 mm**，红色顶点比例 **92.57%**。这仅是合成输入的接口和算法检查，**不是本轮真实场景重建精度**。

详细结果见 [mock_results.json](mock_results.json) 与 [原始测试记录](../validation/RESULTS.md)。

### 6.2 正式扫描性能

| 指标 | 正式扫描记录 |
|---|---:|
| 最近最多 512 个有效结果的输入至融合延迟 P50 | 27.91 ms |
| 同上 P95 | 417.77 ms |
| 融合前过期候选帧计数 | 278 |
| 融合完成较慢计数 | 8 |
| TF/模型不匹配检查命中 | 2 次检查 |

这些统计来自冻结后保存的检查记录。TF 不匹配计数按检查尝试累积，不能直接解释为两个独立姿态。RGB-D 接收计数在冻结后仍会增加，因此本报告不以它计算扫描成功率。

融合前要求输入新鲜并有匹配的静止反馈；静态重建中已完成但耗时较长的融合会保留并计数。延迟统计不包含独立网格打包发布线程的全部耗时，不能直接作为端到端 RViz 延迟。

配置的 5 Hz 是处理上限，移动/停稳检查、初始化、系统负载和过期丢弃都会影响实际完成率。本次未进行严格受控的持续吞吐率或与 ESDF 的同条件速度对照。

## 7. 本轮异常与处理

准备正式扫描时，真实 `/joint_states` 发布者数量变为 0，`controller_manager` 服务不可发现，虽然驱动进程仍在。重建节点等待反馈，没有用旧姿态继续融合，新会话保持 0 帧。

随后重启 UR 驱动，保持运动控制器关闭，并再次等待操作员启动 External Control。驱动回连、关节发布者和控制器服务恢复后，正式扫描能够继续融合，最终完成本报告中的 859 帧结果。

节点已提供 `WAIT_JOINT_FEEDBACK`、关节样本数量和反馈年龄，用于区分输入缺失与尚未停稳。**本轮没有定位底层驱动/DDS 异常的根因，不宣称已经彻底解决该问题。**
